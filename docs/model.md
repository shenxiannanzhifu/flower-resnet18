# v0.3：从图片到手写 ResNet-18

本文说明 v0.3 的模型和数据接口；`check_model.py` 始终使用随机初始化权重检查形状，不加载训练成果。v0.4 已增加小规模训练、保存及重载，见 [训练说明](training.md)。下文“本版”指 v0.3 结构检查阶段，历史报告不改写。

## 运行与阅读顺序

在项目根目录运行：

```powershell
& '.\.venv\Scripts\python.exe' scripts\check_model.py --device cpu
& '.\.venv\Scripts\python.exe' scripts\check_model.py --device cuda
& '.\.venv\Scripts\python.exe' -m unittest discover -s tests -v
```

成功标志分别是 `MODEL CHECK PASSED` 和 `Ran 28 tests ... OK`。GPU 不可用时明确报错，可使用 CPU 命令。默认批量为 8，显存紧张时加 `--batch-size 2`；这只是结构检查批量，不是已确定的正式训练配置。

日常 JSON 输出在 `reports/local/model-cpu` 或 `reports/local/model-cuda`，不进入 Git；本次已验收证据在 `reports/v0.3`，不会被默认命令覆盖。首次在新机器上须先按 README 建环境、运行 `download_data.py`、`prepare_data.py`、`verify_data.py`，再运行模型检查。

建议按 `src/model.py` 的 BasicBlock → ResNet18 → `src/data.py` → `scripts/check_model.py` 阅读；测试中的已知数值例子可帮助理解残差连接。

## 图片怎样变成张量

`configs/model_data.json` 明确指定原图目录、`data/processed-v0.2.1` 和新版 `reports/v0.2.1/summary.json`。Dataset 初始化时比对总清单 SHA-256、划分配置、类别映射及当前子集 CSV，拒绝混用 v0.2 的清单和 v0.2.1 统计。全量原图哈希及重复关系由 `verify_data.py` 单独复核，不在每个 epoch 重算。

`FlowerDataset[index]` 返回 `(image, label, relative_path)`：图像是 float32 的 `[3,224,224]`，标签是整数，路径用于追踪样本。读取时应用 EXIF 方向、转换 RGB；PIL 图片在退出上下文后关闭，缺失/损坏图片给出具体路径。

| 使用场景 | 空间处理 | 原因 |
| --- | --- | --- |
| 训练集 | 随机面积裁剪 0.7–1.0、长宽比 0.75–4/3，缩放 224×224，50% 概率水平翻转 | 增加训练视图变化；这些是初始方案，尚未通过训练证明效果 |
| 验证/测试及未来推理 | 短边缩放到 256，中心裁剪 224×224 | 同一图片处理固定，便于公平比较；本版仅实际读取 train/val 图片 |

两种处理均使用双线性插值和抗锯齿，随后 `ToTensor` 把 0–255 RGB 转为 0–1 CHW，再逐通道归一化：`(pixel - mean) / std`。归一化后出现负数是正常现象。

均值约 `[0.469117, 0.426852, 0.306243]`，标准差约 `[0.302285, 0.272450, 0.297913]`，程序直接读取 JSON 中的完整精度。这些来自 2,564 张训练原图的全部 RGB 像素（按像素数量加权），没有经过缩放、裁剪或增强；不是增强后的精确均值，也不是 ImageNet 的统计量。验证/测试图片不参与估计。

DataLoader 将多张图堆叠成 `[N,3,224,224]`，将标签转为 int64 `[N]`；仅训练子集打乱，最后不足一个批次的样本仍保留。固定 Python、NumPy、torch 种子与打乱生成器，当前环境可复现检查中的增强和顺序，不承诺跨硬件/版本逐位相同。

## 残差连接为什么要匹配尺寸

一个 BasicBlock 计算 `ReLU(F(x) + shortcut(x))`。主支路 `F` 为 3×3 卷积 → BN → ReLU → 3×3 卷积 → BN；第二个 BN 后先相加，再做最终 ReLU。跳跃支路让输入信息和梯度拥有更直接的通路，主支路学习需要改变的部分，有助于深层网络优化，但不能保证本数据集训练效果。

同通道、步长 1 时，`shortcut(x)=x`。如果通道从 64 变成 128，或步长 2 让宽高减半，不能直接相加；投影支路用 1×1 卷积和 BN 同步改变通道/尺寸。投影采用相同 stride，因此奇数尺寸也可匹配，例如 15×17 经 stride 2 变成 8×9。

单元测试把主支路置零，要求输出真的等于 `ReLU(x)`；另用手工设置的 1×1 权重核对投影数值。这能检出“形状正确但漏加跳跃支路”的错误。

## ResNet-18 的形状

采用标准后激活 BasicBlock 与 `[2,2,2,2]` 四组结构，全程只使用 `torch.nn` 基础层。18 层按惯例是首层卷积 + 16 个块内卷积 + 最后全连接；不把三处投影卷积计入型号的“18”。五类输出共 **11,179,077** 个参数。卷积随机使用 Kaiming 初始化，BN 初始缩放 1/偏置 0，全连接权重从小幅正态分布初始化。

| 位置 | N 张 224×224 图片的形状 |
| --- | --- |
| 输入 | `[N,3,224,224]` |
| 7×7 首层卷积，stride 2 | `[N,64,112,112]` |
| 最大池化 | `[N,64,56,56]` |
| layer1：64 通道，2 块 | `[N,64,56,56]` |
| layer2：128 通道，首块降采样 | `[N,128,28,28]` |
| layer3：256 通道，首块降采样 | `[N,256,14,14]` |
| layer4：512 通道，首块降采样 | `[N,512,7,7]` |
| 自适应平均池化、展平 | `[N,512,1,1]` → `[N,512]` |
| 全连接分类层 | `[N,5]` |

输出五列按 `daisy=0, dandelion=1, roses=2, sunflowers=3, tulips=4` 解释。当前只检查 logits 的形状和有限值，不把随机分数称作有效预测。模型末尾没有 Softmax，因为后续 `CrossEntropyLoss` 接收 logits；需要展示概率时在推理入口另外转换。

## eval 与 inference_mode 的区别

`model.eval()` 改变 BN 等层的行为：BN 使用运行均值/方差，不更新它们。它本身不会关闭梯度记录。`torch.inference_mode()` 关闭本次前向的自动求导开销，它本身不会切换 BN 模式，所以检查时两者一起使用。这里没有训练，BN 使用的仍是初始运行统计，不能据此报告分类成绩。

“从训练子集取图”与“把模型设为 train 模式”是两件事。v0.3 取训练子集验证随机增强和数据接口，但完整模型始终处于 eval 模式。v0.4 才会在训练中启用 train 模式、计算损失、反向传播并更新参数。

## 迁移学习的概念与本项目边界

迁移学习通常复用在大数据集预训练的特征，再替换分类层；可先冻结骨干只训练新分类头，也可用较小学习率微调整个网络。它常有助于小数据任务，但效果取决于领域差异和预处理，不能预先承诺提升。

本项目从基础组件手写 ResNet-18 并从随机参数开始，未下载或加载预训练权重。了解上述思想满足 PDF 的原理学习部分；不能用调用现成 ResNet 或迁移学习替代手写残差块的要求。

## 本次发现的问题与适用边界

诊断性尝试双 worker 时，当前 Codex 受限 Windows 环境创建 Python 多进程队列失败，最小复现落在管道 `CreateFile`，返回 WinError 5。最终接口固定 `num_workers=0`，去掉未验证成功的多进程选项，CPU/CUDA 均重新通过。这不代表所有 Windows 环境都不能多进程加载；本次没有修改系统权限。具体失败与修正见 `reports/v0.3/acceptance.md`。

随机裁剪可能切掉花朵，中心裁剪也可能遗漏边缘目标；当前是合理初始配置，效果需正式实验检验。验证只覆盖 CPU/CUDA 各两个真实批次与残差边界，没有完整训练或测试集指标，也未验证其他机器。后续 v0.4 实现训练试运行、保存/加载和一次预测，不把试运行当正式成绩。
