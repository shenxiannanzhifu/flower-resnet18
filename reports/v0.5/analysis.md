## 六个高置信度错误的目视复核

按测试 softmax 最大概率降序选择前六个错误，选择规则在评估代码中预先固定。下图每例左侧是原图缩略图，右侧是实际用于模型的中心裁剪。全图已查看，未声称逐张人工审核全部 549 张图片。作者/来源/CC BY 2.0 许可及修改说明见 `test/image_attributions.csv`；编号对应 `test/error_examples.csv`。

![高置信度错误：原图与模型输入](test/error_examples.png)

| 编号 | 真实标签 → 预测 | 观察与边界 |
| --- | --- | --- |
| E01 | daisy → dandelion，p≈0.995 | 原图花朵在左侧；中心裁剪后花朵几乎完全消失，输入主要是树皮和石面。这直接展示了固定中心裁剪的局限，不能把输出高分解释为可靠识别。 |
| E02 | roses → dandelion，p≈0.969 | 图像呈浅色装饰玫瑰外观，与普通自然花卉实拍不同；可能有领域差异。没有凭目视确定材质或改变标签。 |
| E03 | roses → tulips，p≈0.967 | 远景群花、背景和红色团簇占较大比例，单朵细节较小。这里只记录视觉特征，不据此断定具体致错因素。 |
| E04 | roses → tulips，p≈0.964 | 原始路径是 `roses/14381787252_e8e12e277a_n.jpg`，图中花形目视更像郁金香，属于疑似原始标签噪声。为避免按测试预测改答案，保留 roses 原标签并继续计为错误。 |
| E05 | sunflowers → dandelion，p≈0.959 | 大朵向日葵只显示局部，中心裁剪进一步减少完整轮廓；模型仍可能混淆黄色花朵。 |
| E06 | sunflowers → dandelion，p≈0.945 | 小型黄色花朵，外观与典型大花盘向日葵不同，类别定义/标签是否准确需要额外人工植物学核查；本版不改原标签。 |

发现测试集疑似错标不等于可以修改后重新报一个更高分数。这些记录属于局限说明；如果将来开展独立数据审计，应单独版本化数据并重新安排评估，不能把本次已看过的测试集继续当作未见数据。中心裁剪或增强的改进也需要基于训练/验证资料设计和验证，不能围绕这六张测试图片调参。

## 设备与效率

本次训练累计数据加载约 537.19 秒、GPU 计算及传输/统计约 184.96 秒，前者占两项之和约 74.4%；完整过程还包括验证、保存和重载。正式规模下加载已是主要耗时来源，单进程不是最优吞吐配置，但约 14 分钟已经完成本次实验，所以没有中途修改环境或改变既定方案。

PyTorch 峰值 allocated memory 为 852.13 MiB，这是进程张量分配统计，不是整机显存或可保证的下一次需求。上述时间是实际本机运行记录，不是隔离其他系统活动的标准基准，不能直接推广到其他硬件。若未来需要缩短大规模训练时间，可以单独验证并行加载或缓存方案；当前 Windows 管道权限根因仍未解决。
